## A. 立住了的（按可信度排）

### A1. 凸组合把两个本该自由的系数绑死了，线外的点更好
`D_b+(1−λ)τ_D+λτ_A` 强加 **τ_D = 1−λ**。解开之后：

| | IFEval inst-strict | MATH-500 官方 |
|---|---:|---:|
| 凸组合最佳 | 72.8 (λ=0.6) | 45.0 |
| **(τ_D=0.9, τ_A=1.1)** | **79.6** | **51.0** |

IFEval 来自 29 个 arm 的网格，**协议完全一致**（1280 tok/步、T=0.1、top_p 0.9、entropy、全集）；
MATH-500 是官方 lm-eval、n=500、plain prompt、512 tok。
> **已知性**：这个形式论文已有，叫 **direct addition `D_p+β·τ_A`**（`tab_ablation.tex:4,24`），
> IFEval 上报 **77.1 (β=1.1)** 并**加粗为该列最佳**，赢过自家凸组合的 72.8。
> 指标对账：77.1 = IFEval 四指标平均（72.1/79.5/75.0/81.9）。
> **配对检验（2026-10-09 补，零 GPU，n=500，精确 McNemar，样本在 `dream_study/step2_instruct/outputs/official_eval/mathins_m500-*-plain/`）**：
> (0.9,1.1) vs 凸组合 (0.4,0.6)：独对 79 vs 49，**p=0.010**；(1.0,1.1)（不调 α 的 direct addition）vs 凸组合：74 vs 49，**p=0.030**；
> (0.95,0.55) vs 凸组合：63 vs 45，p=0.10；三者 vs parent 均 p<1e-4。
> (0.9,1.1) 是按 IFEval 选的，MATH-500 上没有再挑，所以 MATH-500 这列近似样本外。
> **新的是 MATH-500 那一列（45.0→51.0），ablation 子表 (a) 只有 IFEval/HumanEval/HumanEval。**
> 待核：论文是否真的没报 MATH-500 的 direct addition。

### A2. 凸组合什么时候出事：β\* 大的时候（因为那时 τ_D=1−β\* 被压垮）
| 家族 | 凸组合 β\* | 它导致的 τ_D | 凸组合 vs direct addition |
|---|---:|---:|---|
| Dream-Coder / HumanEval | 0.2 | 0.8 | 凸组合 **赢 1.3** |
| DiffuCoder / HumanEval | 0.2 | 0.8 | 凸组合 **赢 5.5** |
| DreamReasoner / MATH-500 | 0.2 | 0.8 | 凸组合 赢 0.2 |
| Dream-v0 / IFEval | **0.6** | **0.4** | 凸组合 **输 4.3** |
| Dream-v0 / MATH-500 | **0.6** | **0.4** | 凸组合 **输 6.0** |

**完美分离。** 代码家族不是反例 —— 它们的 β\* 本来就小，凸组合白捡了 τ_D=0.8。
**可证伪预言**：解耦只在 β\* 大处有收益，β\* 小处是 no-op。**待跑**：coder 的 (α=0.9, β=0.2)（磁盘上没有）。

### A3. 曲面是平台不是尖峰 → "快速定位"=不要搜
29 点：τ_D=0 → 62.9–63.8（悬崖）；凸组合线 → 74.2–75.9；**τ_D≥0.68 且 τ_A∈[0.8,1.4] → 77.6–79.6**（17 个点，2 分带宽）；τ_D+τ_A=2.6 → 75.7。
峰 79.6 @ (0.9,1.1)；**(1.0,1.1)=79.5，与 29 次实验的最优差 0.1**。
两个支配量跑前就能定：**τ_D 必须保住**（悬崖）、**τ_D+τ_A ≈ 1.6–2.4**。

### A4. self-rescaling 的最优 α\* 一致地略小于 1，可作为解耦的锚
`D_b+α·τ_D`（无 AR）在 5/5 个 cell 打赢 parent：Dream-v0 α=0.9 (+0.4)、Dream-Coder 0.9 (+1.8)、
DiffuCoder 0.8 (+1.8)、DreamReasoner 0.9 (+1.0)、DiffuCoder-RL 0.7 (+2.7，**比凸组合还高，论文加粗**)。
而 (α\*=0.9, β=1.1) 正是 IFEval 和 MATH-500 的共同最优点。
> 但"先 rescale 再加"**优于**"直接加（α=1）"的幅度只有 +1.0 / +0.1，两个 cell —— **这一条还没立住**。
> 立住的是"两者都远好于凸组合"。

### A5. τ_A 杀 EOS padding；τ_D 决定还能不能写出答案 —— 两件事
- **padding 是 τ_A 杀的，τ_D 保不住**：固定 τ_D=0.9，τ_A 0→1.1 使每题 EOS 从 **247 → 1**；
  A2D 自己的最佳 merge（0.4,0.6）每题 EOS 已经只有 **1**（parent 是 **264**）。
- **但 padding 没了不要紧**：官方 scorer 在整条 512 token 里找 `\boxed{}`，所以顶cap ≠ 没答上
  （(0.9,1.1) 顶cap 93.8% 而写完率 92.6%，是最高的）。
- **和分数挂钩的是写完率，而它被两个系数同向抬高**：
  固定高 τ_D，τ_A 0→0.55→1.1 → 写完率 **79.6% → 87.4% → 92.6%**；
  相近 τ_A 下 τ_D 0.95→0.4 → 写完率 **87.4% → 68.8%**。
  **→ 凸组合之所以糟，正是因为它强迫你用一个换另一个。**

### A6. 预算翻倍关掉预算通道
512：写完率随剂量 81% → 58.5%（崩）。1024：**73–78%，几乎平**。
"所有 arm 都写完"的固定子集从 42/200 涨到 93/200。

### A7. 两种架构"停"的方式不同（实测）
全画布（Dream-v0）：已提交位置 **100%** 的画布，"停"=padding 从哪格开始，parent 每题 264 个 EOS。
块扩散（DreamReasoner b32）：已提交位置是**连续前缀，500/500**，只占 8192 的 **11.7%**；
每题 EOS 中位 **16 ≈ 半个 block**（答案在 block 中间写完→补满该 block→halt）。
→ "EOS 占提交"**不可跨架构比**（块扩散的分母被从未访问的格子稀释）。

### A8. DreamReasoner：MATH-500 饱和，AIME 才有信号，且损伤是纯推理
MATH-500（`-m500-8k` 组，n=500）：写完acc **95.9–96.5**、整条 λ 曲线 null（配对 |Δ|≤0.6，p≥0.6）。
AIME24+25（n=60）：**写完率除 λ=0.6 全是 100%**（预算通道饱和）→ 变化 100% 是推理。
λ=0.2 为 68.3；**λ=0.6 为 36.7，配对 −27.3，p=0.001**；**λ=0.3 为 46.7，配对 −21.7，p=0.001**
（曲线**非单峰**，Bonferroni 0.01 下这两个都存活）。

### A9. help 会饱和然后消失；harm 单独爆炸
AIME（help=parent 错&merge 对，harm=反之）：help 11→**13**→4→8→**5**，harm 4→3→7→5→**14**。
**不是"好处坏处一起放大"。** → **"在高 λ 保留 help 剔掉 harm"在 DreamReasoner 上不成立，因为高 λ 上没有 help 了。**
> 用户记的那句"merge 越多 help/harm 都涨"**不在投稿 appendix 里**，在 `dream_study/README_ZH.md:27-28`
> 和 `step2_instruct/results/README.md:123-124`，且**证据全是 Dream-v0/IFEval 与 DreamCoder/HumanEval，
> 零个 DreamReasoner 数据点**。

### A10. help/harm 的性质 = 长度
MATH-500：**被帮助的题** parent 11127 字符 → merge **5364**（更短，47/68）；
**被损害的题** parent 8060 → merge **13401**（更长，48/59）。
**help = 让它收住并写出答案；harm = 让它写不完/绕飞。** 被损害的 59 个里 **28 个 pred 完全为空**。

### A11. help 和 harm 分不开（按题目属性）
唯一有预测力的题目侧特征是 parent 输出长度（难度代理），但长输出区同时装着 45/68 help 和 30/59 harm，
桶内 help 占比 0.56–0.67 —— 它选出的是"易变区"。AIME 上被帮助的题号随 λ 大换血（Jaccard ≤0.50）。
事后按输出属性部分可行（"merge 比 parent 长 ⇒ harm" 召回 0.81 精度 0.70；28/59 的 harm 是空 pred，
零成本可检测、可回退 parent）。
**逐题最优 λ 的 oracle = 80.0% vs 最佳单一 λ 68.3%（+11.7 headroom），但没找到能实现它的预测器。**

## B. 今天撤回的（连同原因）

| 撤回的说法 | 为什么错 |
|---|---|
| "扩散模型先定长度、从右往左扫 EOS、第 1 步就在最右端" | `dream_step_divergence.py` 的 `probs_argmax` **没加 conf_temp=0.1 锐化**，走的是 `lockstep_port.py:46` 注释里写明会退化成 all-EOS 的那条路。官方轨迹（带锐化）**近乎严格从左往右**（corr=+1.000），长度决定是**写完内容后 emergent 的**，不是提前的 |
| "保住 τ_D 才保住收尾" | 错。`0.9τ_D+1.1τ_A` 的 τ_D 完好、padding 照样归零（每题 1 个 EOS）、顶cap 93.8%，**但它是最好的 arm**。见 A5 |
| **"过度 merge 不伤推理，只伤收尾"** | **Dream-v0 上不可验证**：写完率崩塌恰好把难题从配对比较里审查掉了（高剂量下交集只剩 42/200 题，且全是简单题，准确率 76–86%）。四个配对点估计全为负且随剂量递增（−0.9/−2.1/−3.3/−3.0），是**功效不足的 null**。DreamReasoner/AIME 上（写完率 100%、可测）结论相反且显著 |
| "论文系统性低报自己方法（低报 4.1 分）" | **削弱** —— 它依赖上一条 |
| "块扩散丢 EOS 代价 −18.8 分 + 8.5× 算力" | **归因撤回** —— 用的是 `drtr` = transfer-only `D_b+β·τ_A`，**锚在 Base**、τ_D=0。Base 自己就不收尾（83.8% 顶cap、81/500 吐 EOS），所以那是继承的，不是过度 merge 造成的 |
| idea 1 的 "λ" 的含义 | `merge_manifest.json`：λ 是 **τ_A 系数**，**τ_D = 1−λ**。`merge_l10`/`transfer_a1X` 的 **τ_D 是 0**。所以那条"剂量轴"同时在加 AR 和删 τ_D |
| "AIME 上 λ=0.3 的反常是噪声" | 用了**非配对**标准误（±12.7）。配对精确 McNemar 给 **p=0.001**。小 n 上不能用非配对 SE 下"是噪声"的结论 |
